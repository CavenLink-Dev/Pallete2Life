Redesign the existing HueSet “Better Interface” learning experience.

Route:
`/better-interface`

IMPORTANT REFERENCE SITES:

https://developer.apple.com/documentation/

https://developer.apple.com/design/resources/

Also use Apple’s Human Interface Guidelines as a reference for how design knowledge is organised:

https://developer.apple.com/design/human-interface-guidelines/

I want the Better Interface experience to take strong inspiration from the STRUCTURE, INFORMATION HIERARCHY, NAVIGATION, DENSITY, AND LEARNING EXPERIENCE of Apple Developer Documentation and Apple Design Resources.

Do NOT copy Apple branding or recreate Apple’s website pixel-for-pixel.

Keep HueSet’s own:

- logo
- icon
- dark charcoal background
- baby-blue accent
- white text
- visual identity

The goal is:

Apple-style clarity and documentation structure
+
HueSet branding
+
a course specifically for learning website and app design.

==================================================
CORE EXPERIENCE
==================================================

Better Interface is not a marketing page.

It is a real design-learning library and course.

It should feel like:

documentation
+
design education
+
practical reference material

The user should be able to enter and immediately:

- browse design topics
- search for something
- open a lesson
- understand where they are
- move between related subjects
- see practical examples
- continue their course progress

==================================================
LAYOUT
==================================================

Use a documentation-style structure.

Desktop should ideally include:

LEFT:
Persistent course/topic navigation.

CENTER:
Main lesson/article content.

OPTIONAL RIGHT:
Compact on-page table of contents for longer lessons.

TOP:
Search and lightweight navigation.

The main content should always be the visual focus.

Do not surround everything with large cards.

Use typography, spacing, dividers and hierarchy to organise information.

==================================================
SEARCH
==================================================

Search should be important.

Allow someone to search things such as:

“colour contrast”

“button spacing”

“navigation”

“typography”

“paywall”

“responsive layout”

Results should quickly take them to the relevant lesson or design topic.

Where useful, support suggestions and category filtering.

==================================================
LESSON DESIGN
==================================================

Individual lessons should resemble high-quality technical/design documentation.

Example:

Visual Hierarchy

Short introduction

Overview

Principles

Examples

Bad vs Better

Practical guidance

Common mistakes

Rules of thumb

Interactive example

Related topics

Previous / Next

Do not make lessons feel like blog posts.

They should feel structured and referenceable.

==================================================
VISUAL EXAMPLES
==================================================

Because this is a design course, examples are critical.

Use:

BAD
vs
BETTER

and realistic fictional interfaces.

Teach visually:

- weak vs strong hierarchy
- bad vs good spacing
- low vs good contrast
- poor vs readable typography
- inconsistent vs consistent components
- cluttered vs clear layouts

Allow lightweight interaction where useful.

==================================================
RESOURCE LIBRARY
==================================================

Take inspiration from Apple Design Resources.

Create an area where students can browse practical design resources by type.

For example:

- Website patterns
- App patterns
- Navigation examples
- Paywall examples
- Button examples
- Form examples
- Layout examples
- Figma exercises
- Checklists
- Design-system references

Organise these clearly rather than presenting one giant gallery.

Apple groups resources by platform and type; use the same principle of making a large library easy to navigate. Do not copy Apple’s actual resources. Use original HueSet content.

==================================================
DESIGN PRINCIPLES
==================================================

The learning experience itself should follow principles such as:

- clarity
- hierarchy
- simplicity
- familiarity
- consistency
- accessibility
- flexibility

Every interface element should earn its place.

Do not add decoration simply to make the screen look more interesting.

==================================================
COURSE PROGRESS
==================================================

Keep course progress simple.

Show:

- current topic
- completed lessons
- overall progress
- next lesson

Do not heavily gamify it.

No coins, streaks or unnecessary rewards.

==================================================
HUESET CONNECTION
==================================================

Where relevant, lessons can have secondary actions such as:

Try in Quick Design

Explore Examples

These should support the lesson rather than distract from it.

==================================================
RESPONSIVE
==================================================

Desktop:
Persistent documentation-style sidebar.

Tablet:
Collapsible sidebar where appropriate.

Mobile:
Course navigation becomes a drawer/menu while keeping the lesson highly readable.

Preserve the user’s location and progress across layouts.

==================================================
FINAL GOAL
==================================================

The final experience should feel like:

“Apple Developer Documentation, but for learning practical website and app design through HueSet.”

A user should be able to:

search
→ browse topics
→ open a lesson
→ understand the principle
→ see examples
→ practice it
→ explore related topics

without feeling lost or overwhelmed.
